# 麦当劳活动 / 套餐推荐

## 目的
帮助用户快速了解麦当劳「正在进行的活动」，并按两大类分类展示：
1. **套餐优惠（可购买）**：限时省钱套餐、新套餐、新品、加价购周边、会员卡等
2. **比赛 / 征集（非购买）**：派对、亲子活动、积分抽奖 / 领券放码、开发者征集比赛等

## 何时使用
- 用户问「最近 / 这个月麦当劳有什么活动、优惠、新品」
- 用户按口味、场景、预算或身份（学生 / 亲子等）找活动或套餐
- 用户问「有什么可以参加的」「有什么抽奖 / 领券 / 放码」「麦当劳有什么比赛 / 征集」

## 前置条件
- 已连接麦当劳 MCP，工具 `mcp__mcd-mcp__*` 可用
- 若工具不可用，提示用户在连接器中启用「mcd-mcp」后再试

## 工作流程
1. 确定时间锚点：默认查当月；用户指定日期时，先调用 `mcp__mcd-mcp__now-time-info` 确认当前时间，再传 `specifiedDate`
2. 调用 `mcp__mcd-mcp__campaign-calendar`（用户指定日期时传 `specifiedDate`，格式 `yyyy-MM-dd`）获取活动日历
3. **非购买类补全（三路合并，缺一不可）**：
   - 调用 `mcp__mcd-mcp__query-lottery-info` 获取积分抽奖活动（奖品、消耗规则、起止时间）
   - 调用 `mcp__mcd-mcp__available-coupons` 获取麦麦省当前可领取的优惠券（放码 / 领券类活动）
   - 读取本 skill 的 `references/external-events.md`，把仍在有效期内的官方征集 / 比赛条目合并进结果（此类活动不在 MCP 内，只能来自该清单）
4. **可购买类补全（价格 + 套餐内容）**：对每个可购买套餐 / 新品：
   - 先调用 `mcp__mcd-mcp__query-nearby-stores`（`searchType=2`，传 `city` 与 `keyword`，`beType=1`）获取一个 `storeCode`
   - 再调用 `mcp__mcd-mcp__query-meals`（`storeCode` + `orderType=1` + `beType=1`），按名称匹配到商品 `code`，读取 `currentPrice` / `originalPrice`
   - 再调用 `mcp__mcd-mcp__query-meal-detail`（`storeCode` + `orderType=1` + `beType=1` + `code`）获取套餐所含食物与可特调项
   - 兜底：日历文案中已写明价格（元）可直接引用；文案写明了组成的直接引用；两者都拿不到时注明「以门店实际为准」，不得编造
5. 按「分类规则」归类，按「输出格式」呈现

## 分类规则
- **套餐优惠（可购买）**判据：活动内容涉及具体餐品、新品、套餐、折扣价、加价购、会员卡 / 学期卡等「花钱可得」的消费项目
- **比赛 / 征集（非购买）**判据：派对、读书会、亲子活动、积分抽奖、领券 / 放码、游戏过关、开发者征集比赛等「参与性质」活动
- 边界：会员卡 / 学期卡属于「可购买」；积分抽奖、领券、派对应归「非购买」

## 输出格式
分两类，从上到下依次列出。可购买类每条固定四行（名称 / 价格 / 套餐内容 / 参与要求 / 活动入口）；非购买类每条固定三行。

```
### 一、套餐优惠（可购买）
- 活动名称：{活动标题}
  - 价格：{现价（及原价）；来源为 calculate-price 时单位为分需 ÷100，query-meals 的 currentPrice 与日历文案价格均为元，直接引用；周边加价购写「消费 X 元加价得」}
  - 套餐内容：{套餐所含食物，来自 query-meal-detail 或日历文案；周边类写物品本身；无则写「单品」}
  - 参与要求：{从活动内容介绍提炼，如「任意餐品消费加 39.9 元」「学生身份」；无则写「无门槛」}
  - 活动入口：{渠道，如「麦当劳 APP / 小程序 / 到店」；文案含链接时给链接}

### 二、比赛 / 征集（非购买）
- 活动名称：{活动标题}
  - 参与要求：{……}
  - 活动入口：{渠道或跳转链接；来自 external-events.md 的条目必须给出清单中的链接}
```

## 关键注意事项
- `campaign-calendar` 返回字段为「活动标题 / 活动内容介绍 / 活动图片介绍」，**没有独立的「参与要求」和「跳转链接」字段**：参与要求从内容介绍中提炼；入口写渠道（麦当劳 APP、小程序、到店），**不要虚构 URL**
- 非购买类必须跑完第 3 步的三路合并，漏掉 `available-coupons`（放码）或 `external-events.md`（征集比赛）都算输出不完整
- 可购买类必须跑第 4 步，输出缺「价格」或缺「套餐内容」都算不完整
- 图片字段是 `<img src=...>`，仅在需要时展示图片 URL，不作为跳转入口
- `campaign-calendar` 文案与 `query-meals` 的 `currentPrice` / `originalPrice` 均为「元」，直接引用；仅 `calculate-price` 的价格单位是「分」，需 ÷100 转「元」
- 只列真实存在、进行中或已预告的活动；已结束的活动标注「已结束」
- 若返回为空或异常，如实说明，不编造活动
- 用户明确想下单时，再进入门店选择 + `calculate-price` + `create-order` 流程，不主动下单
- `available-coupons` 只做展示；用户明确要领券时才调用 `auto-bind-coupons`，领券前先展示将领的券并确认
